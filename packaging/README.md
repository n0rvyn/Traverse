# Linux package build and release

Work in progress. Build recipes exist; package compatibility is claimed only after installed-artifact checks pass on the declared release/desktop/architecture. Current production onboarding/default-port/Wayland work remains on the roadmap.

`build-runtime.sh` runs inside Ubuntu22.04, building pinned GStreamer1.26.11 and patched libnice0.1.24. It creates a private runtime closure under `/opt/traverse`; it does not replace system media libraries. The payload includes the external xmessage executable used by the local Stop sharing dialog, required shared libraries and plugin scanner. An existing X11 display/core fonts and the host CA trust store remain prerequisites. The software-only baseline targets glibc2.35 or later; GPU/Wayland support requires its separate backend/hardware evidence.

CI builds native x86_64 and arm64 artifacts on their respective runners. It records the resolved baseline image identity, source commit, dependency versions and payload hashes. Pinning source archives is not a claim of bit-identical output across changing distribution repositories; independent rebuild/provenance comparisons are still required.

Artifacts: `.deb`, `.rpm`, portable `.tar.gz`, SHA256SUMS and corresponding third-party source archives/patch/build recipe/notices. No build toolchain is needed on the installation host. The installed launcher runs as `traverse --config FILE` (default `$XDG_CONFIG_HOME/traverse/config.json`). It supervises its owned desktop/network children and stops them on exit or crash. Copy the packaged `config.example.json` and supply the domain/certificate/key; its port defaults to443 and is editable. Integrated first-run host controls remain a later phase. `traverse --check-runtime`, `traverse adapter ...` and `traverse service ...` remain available for diagnostics. Package installation does not activate capture or a listener. Legacy configurations use their existing ports and separate example.

Stable publication requires `vX.Y.Z` matching the CMake version, with the exact tag commit reachable from fully fetched `origin/main`. A dev-only descendant fails even if main is its ancestor. The release rebuild uses the validated commit SHA, runs package installation/relocation/dialog checks and publishes only its own artifacts after checks. Branch/PR workflows have read-only tokens and do not release or receive publishing credentials. Daily builds remain workflow artifacts.

The runtime check verifies the bundled TURN version and encrypts/decodes synthetic VP8 frames without opening a display or network listener. Bundled NSS providers include their matching integrity files; relocation tests also remove a provider or required executable to verify that an incomplete payload fails. Installed TURN tests exercise authentication, denied destinations, actual UDP echo and channel data. Plugin discovery alone does not prove encrypted media works.

The native TLS front end is packaged with pinned coturn4.18.0. Versioned standalone configuration selects one editable public TCP/UDP port, default443. TLS routes only to fixed private HTTP/TURN backends, including numeric IPv6 TLS listeners; direct ICE uses UDP and authenticated TURN/TLS provides TCP fallback. The explicit `--internal-http` service mode accepts only numeric loopback bindings behind a TLS terminator; ordinary diagnostic service launches still require HTTPS certificates. Service listeners use address reuse for restart and reject a second live listener on the same address/port.

DEB/RPM installation generates a root-owned plugin registry without capture or listeners and grants only binding capability to a libc-only helper. Isolated package tests preserve the unprivileged UID/GID, inspect every live thread, reject hostile loader/plugin environment and writable runtime files, and read back metadata after reinstall. The test observer's extra capability and low-port threshold apply only inside fresh container namespaces. Portable archives have no implicit capabilities. See [installation](../docs/install.md).
