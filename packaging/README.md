# Linux package build and release

Work in progress. Build recipes exist; package compatibility is claimed only after installed-artifact checks pass on the declared release/desktop/architecture. Production onboarding, external reachability, certificate enrollment and Wayland work remain on the roadmap.

`build-runtime.sh` runs inside Ubuntu22.04, building pinned GStreamer1.26.11 and patched libnice0.1.24. The recipe also builds the pinned PipeWire1.6 client and libei1.5 provider for the internal Wayland backend checks; it keeps the distribution compositor and PipeWire daemon. Meson1.6.1 and Jinja2 3.1.6 are build-only tools. It creates a private runtime closure under `/opt/traverse`; it does not replace system media libraries. The payload includes the external xmessage executable used by the local Stop sharing dialog, required shared libraries and plugin scanner. An existing X11 display/core fonts and the host CA trust store remain prerequisites. The software-only baseline targets glibc2.35 or later; GPU/Wayland support requires its separate backend/hardware evidence.

CI builds native x86_64 and arm64 artifacts on their respective runners. It records the resolved baseline image identity, source commit, dependency versions and payload hashes. Pinning source archives is not a claim of bit-identical output across changing distribution repositories; independent rebuild/provenance comparisons are still required.

Artifacts: `.deb`, `.rpm`, portable `.tar.gz`, SHA256SUMS and corresponding third-party source archives/patch/build recipe/notices. No build toolchain is needed on the installation host. The installed launcher runs as `traverse --config FILE` (default `$XDG_CONFIG_HOME/traverse/config.json`). It supervises its owned desktop/network children and stops them on exit or crash. Copy the packaged `config.example.json` and supply the domain/certificate/key; its port defaults to443 and is editable. The current working-tree recipe also builds an explicit `traverse-host` entry with separate system Qt6.2.4+/OpenSSL3 dependencies; it excludes Qt from the private media closure and gives the UI no capabilities. This is still private candidate work, separate from published CI artifacts. `traverse --check-runtime`, `traverse adapter ...` and `traverse service ...` remain available for diagnostics. Package installation does not activate capture or a listener. Legacy configurations use their existing ports and separate example.

Stable publication requires `vX.Y.Z` matching the CMake version, with the exact tag commit reachable from fully fetched `origin/main`. A dev-only descendant fails even if main is its ancestor. The release rebuild uses the validated commit SHA, runs package installation/relocation/dialog checks and publishes only its own artifacts after checks. Branch/PR workflows have read-only tokens and do not release or receive publishing credentials. Daily builds remain workflow artifacts.

The runtime check verifies the bundled TURN version and encrypts/decodes synthetic VP8 frames without opening a display or network listener. Bundled NSS providers include their matching integrity files; relocation tests also remove a provider or required executable to verify that an incomplete payload fails. Installed TURN tests exercise authentication, denied destinations, actual UDP echo and channel data. Plugin discovery alone does not prove encrypted media works.

The pinned private libnice build includes the DNS-completion repair in `patches/`: a failed public STUN/TURN lookup finishes its discovery work so available local candidates can complete ICE gathering. Native regression checks also retain pending-resolution ordering and stream/close cancellation. This does not remove public discovery or accept an incomplete gathering result.

The native TLS front end is packaged with pinned coturn4.18.0. Versioned standalone configuration selects one editable public TCP/UDP port, default443. TLS routes only to fixed private HTTP/TURN backends, including numeric IPv6 TLS listeners; direct ICE uses UDP and authenticated TURN/TLS provides TCP fallback. The explicit `--internal-http` service mode accepts only numeric loopback bindings behind a TLS terminator; ordinary diagnostic service launches still require HTTPS certificates. Service listeners use address reuse for restart and reject a second live listener on the same address/port.

The standalone frontend validates and reloads replaced certificate/key files without restarting desktop/media children or established TLS sessions. It checks hostname/IP SAN, chain, key and validity using the selected host trust sources; expiry blocks new TLS connections even when a pending handshake started earlier. A private per-instance snapshot feeds supervisor diagnostics for renewal/rejection/expiry and invalid metadata. Installed tests cover existing TURN/input continuity, relative trust sources across helper environment clearing and every frontend thread's zero-capability state. Certificate enrollment/scheduled issuance and the integrated host UI remain separate work.

DEB/RPM installation generates a root-owned plugin registry without capture or listeners and grants only binding capability to a libc-only helper. Isolated package tests preserve the unprivileged UID/GID, inspect every live thread, reject hostile loader/plugin environment and writable runtime files, and read back metadata after reinstall. The test observer's extra capability and low-port threshold apply only inside fresh container namespaces. Portable archives have no implicit capabilities. See [installation](../docs/install.md).

No project license has been selected. Bundled third-party components retain their licenses and accompanying source/notice obligations; packaging does not relicense them.

The private Wayland worker is built from the same native guardian core as the protocol checks and installed at `libexec/traverse/traverse-wayland-guardian`. Its closure includes the libei client; the libeis test server stays outside the payload. Installed DEB/RPM and portable checks use an external C++ owner and private D-Bus fixture to verify actual replies, loading origins, cancellation and child reaping. This packaging boundary does not select the Wayland backend in the host or prove compositor/Chrome compatibility; those require the separate desktop and integration checks.

The certificate issuer is a separate static Go executable, outside the capture, encoding and input processes. The build downloads a checksum-pinned Go toolchain into its own work directory, verifies the three compiled ACME dependencies, and includes their notices and corresponding sources. Installation needs no Go toolchain and creates no CA account. Private-CA tests exercise real TLS-ALPN validation, renewal, account recovery and rejected proofs; installed-helper tests run without privileges and check nonce retry and error redaction. The native manager owns certificate admission and renewal scheduling. First-run certificate controls remain separate work.

Configured offline mode uses `"certificateSettings": {"mode": "local"}` in a versioned configuration, instead of the top-level `certificate` and `privateKey` fields. It generates a local authority restricted to the configured hostname or IP address, without contacting a public CA. The CA lasts ten years; leaf certificates last ninety days and renew locally after sixty days. Port changes preserve the authority. Changing the hostname requires trusting a new authority; an expired or damaged initialized authority fails visibly instead of silently replacing client trust. IPv4-mapped IPv6 addresses are normalized to IPv4 in this mode.

Each Chrome client needs deliberate trust of the public CA certificate once. The CA private key stays on Linux; installation and startup never add client or system trust. Private native-host candidates now contain actual first-run setup, Settings and public export controls. Actual DEB/RPM/portable setup and relaunch checks passed; exact-package Chrome sessions lose desktop-adapter IPC and remain under diagnosis. Native ARM host-window and full RPM legacy Stop acceptance are still open. Local candidate verification stays outside public history; hosted CI acceptance is pending. The configured backend was checked in unpublished x86_64 DEB, RPM and portable candidates, including an isolated ordinary Chrome client with actual video, keyboard control and renewal. This is separate from current GitHub CI, full GNOME/KDE onboarding and physical-hardware latency acceptance.

The certificate helper must match the current checkout: assembly verifies its executable hash, source archive hash and every non-vendored project source file against the build archive. Installed checks compare the intended build manifest and every payload file before testing behavior. These checks reject stale cached helpers and incorrect local artifact selection.
